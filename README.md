# フィールドワーク LIVE

中高生のフィールドワーク向け Web アプリ。教員が資料・地図を操作し、生徒の端末が同じ状態へ追従します。生徒は登録不要で参加コード・QRから入れます。教員のメール認証と Supabase プロジェクトが必要です。

## 現状と前提

これは React/TypeScript/MapLibre/Supabase を使った実装です。**Supabase プロジェクトが未接続の状態では、画面は表示できますがセッション作成・同期は動きません。** この配布物には実際の Supabase URL・publishable key を含めていません。セットアップ後はブラウザから使用できます。コードはビルド検証済みですが、この作業環境では Supabase 接続と教員・生徒の二端末ブラウザ試験は未実施です。学校で使う前に下の試験を行ってください。

### 実装済み

- 教員メールログイン、セッション作成、推測しにくい18桁の16進数参加コード、QR・URL、匿名生徒参加、現在の接続人数の目安、終了
- JPEG/PNG/WebP（10 MB 以下）、非公開 Storage、署名付きURL、写真変更・ズーム・パン・相対座標の書き込み（線・丸・矢印・囲み・フリーハンド・消しゴム・全消去）
- 国土地理院標準地図と「れきちず」のMapLibre表示、地図カメラの同期、地理座標に残る書き込み
- 写真と地図の任意2画面比較。縦画面は上下、広い画面は左右。地図2枚は共通カメラ（center/zoom/bearing/pitch）
- 教員の現在地共有（最新位置のみ上書き）、生徒本人の位置を端末内で表示。許可を拒否しても他の機能は使用可
- 課題地点、説明、問い、参考URL、写真、読む／完了／短文回答、到着半径30/50/100/200mの端末内判定、人数での進捗
- LIVE／自由閲覧、全員をここに戻す、DBの状態復元、接続切れ表示、PWAのアプリシェル

### 制限

- 到着判定は生徒端末内で行います。位置の偽装やGPS誤差に対する成績評価用の証明にはなりません。生徒位置はサーバーへ送りません。
- 「接続中」は Presence の目安です。通信断時に少し遅れて変わる場合があります。
- PWA はアプリシェルのみをキャッシュします。オフラインで新しい地図タイルや課題を読み込むことはできません。表示済み教材は通信断時に画面へ残ります。
- 地図の書き込みは2画面の両地図に表示されます。れきちずの元のタイルとスタイルは変更しません。
- iOSでは位置情報はHTTPSのページを開き許可した間だけ利用できます。ブラウザを閉じた後にバックグラウンド位置追跡は行いません。

## セットアップ

1. [Supabase](https://supabase.com/) でプロジェクトを作成します。**Auth → Providers** で Email と Anonymous Sign-ins を有効にします。Email は学校に適切な認証・送信設定を確認してください。
2. SQL Editor で `supabase/migrations/001_init.sql` を一度実行します。テーブル、RLS、非公開Storageバケット、Realtime publication が作られます。既に同名のテーブルがあるプロジェクトでは実行しないでください。専用プロジェクトを推奨します。
3. **Auth → URL Configuration** の Site URL と Redirect URLs に公開URL（ローカルなら `http://localhost:5173`）を登録します。教員のメールリンクが同じオリジンに戻るようにします。
4. `.env.example` を `.env.local` にコピーし、Project URL と **publishable/anon key** を設定します。`service_role` キーやDBパスワードをブラウザ側へ設定しないでください。
5. `npm ci && npm run dev`。同じネットワークのスマートフォンからテストする場合は、HTTPSの公開プレビューを使います。位置情報APIは `localhost` または HTTPS で動きます。
6. 教員側でメールリンクからログインし、セッションを作成。QRを生徒の端末で読み取ります。

```sh
cp .env.example .env.local
npm ci
npm run dev
npm run build
```

## 公開

静的ファイルの `dist/` を HTTPS のホスティングへ配置できます。Supabase 側の認証 Redirect URLs もその公開URLに合わせてください。Viteの環境変数は**ビルド時**に埋め込まれます。公開可能な publishable/anon key だけを入れ、RLSを必ず有効にしてください。

GitHub Pages なら、Repository Settings → Secrets and variables → Actions に `VITE_SUPABASE_URL` と `VITE_SUPABASE_ANON_KEY` を登録し、Actions の Pages デプロイを有効にします。`VITE_BASE_PATH=/repository-name/ npm run build` でサブパスに合わせられます。`dist/`を Pages に配置します。`.github/workflows/pages.yml` に自動デプロイ例を用意しています。QRのURLは実際の公開URLから生成されます。

新しい本番プロジェクトでは、RLS SQLを適用し、匿名認証の利用量、Storage容量、Realtime同時接続数、メール配信設定を管理画面で確認してください。30〜40人で実地試験後に利用を始めてください。

## 教員の操作

1. 「教員として開始」からメール認証、フィールドワーク名を入力してセッション作成。
2. 「参加する」のQRまたはコードを提示。ヘッダーに接続人数。
3. 下の「資料」から地図・れきちず・写真を選び、写真を追加。写真はピンチ／右下の＋−、指で移動。
4. 「2画面」で比較。各画面の「表示を変更」から資料を選択。地図2枚は同じ地点へ追従。
5. 「書く」から道具を選択。地図を動かすときは「動かす」に戻す。「動かす」で地図の中心地点に課題を置ける。
6. 「GPS」で自分の位置と共有・追従を選択。共有は必要なときだけONにする。
7. 自由閲覧のあと「全員をここに戻す」で現在の教員画面に復帰。終了後は「参加する」→「セッションを終了」。

## 生徒の操作

QRまたは参加コードで参加します。LIVE中は教員の画面に追従します。自由閲覧中は地図・写真を動かせます。「現在地」は許可した人だけ使い、位置は教員へ送られません。「課題」から地点を開きます。通信が切れても、表示中の資料を見ながら再接続を待てます。

## 試験手順（公開前に必須）

教員アカウントで1つ、生徒は別ブラウザ／シークレットウィンドウで1つ開き、実際のSupabaseに接続して確認してください。GPSはHTTPSで位置許可し、到着条件は試験用マーカーを現在地近くに作って確かめます。

1. 教員が写真AとBを登録、切り替える → 生徒も切り替わる。
2. 写真を拡大・移動 → 生徒側も同じ箇所。教員が丸を描く → 生徒に同位置で出る。
3. 現代地図を移動・ズーム・回転 → 生徒側が追従。
4. れきちずに切り替え、タイルと出典が表示される。
5. 2画面にして現代地図とれきちずを選択。一方を移動して両方が同地点になる。
6. 教員の現在地共有と生徒本人の現在地を別々にON/OFF。生徒の位置が教員へ現れない。
7. マーカー作成、説明・URL・写真・問いを確認。現在地に近い到着条件の課題が開放され、短文回答／完了数が反映される。
8. 自由閲覧で生徒が操作し、「全員をここに戻す」で再追従。
9. 生徒側の通信を切り、最後の資料が残ることを確認。再接続／再読み込みで最新状態へ戻る。
10. 生徒のブラウザからDBの直接更新を試し、教員状態・教材・マーカー・他人の回答への変更がRLSで拒否されることを確認。

この環境では **1〜10の対向ブラウザ試験は未実施**。本番公開の受け入れ条件にしてください。

## データ・権限

`fieldworks`, `sessions`, `session_members`, `session_state`, `content_items`, `markers`, `tasks`, `task_completions`, `annotations`, `teacher_location` を使用。生徒の位置・移動履歴のテーブルはありません。Storageは非公開バケットで、セッション参加者だけが読み取り、教員だけが書き込みます。教員位置は1行の最新座標を上書きし、共有OFF／セッション終了時に消します。生徒の回答は本人と教員だけが読めます。参加コードを知る人は匿名で参加できるため、校内のみでQRを掲示し、終了時にセッションを閉じてください。
